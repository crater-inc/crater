# SEOキーワード自動抽出システム 設計書

作成日：2026-07-13
オーナー：ケイスケ（クレーター／APOLLOS 代表）

## 1. 目的（何のために作るか）

5つの自社サイトのジャーナル（ブログ／記事）を継続更新するための、**SEOキーワードを自動で抽出・蓄積するシステム**。

朝起きたら「AI社員が勝手にキーワードを用意してくれている」状態をつくる。貯まったスプレッドシートを"記事ネタ帳"として使い、各サイトの記事制作に流し込む。

将来的には他社サービスのSEOキーワード抽出にも同じ仕組みを使い回す（＝クレーター／APOLLOSの資産にする）。

### 前提として捨てた案（YAGNI）
- 「稼働率メーター・アイコンが動く見せ物ダッシュボード」＝自分用には不要と判断し不採用。中身（自動でキーワードが貯まる）だけ作る。
- 「毎朝・数百個の大量抽出」＝実際の更新ペース（週10記事）に対して過剰。使われず死ぬので不採用。

## 2. 対象サイトと キーワード設計方針

全サイト共通の考え方：
**「このサイトに来て発注／購入したくなる人」を幅広く想定 → その人の行動の流れ（導線）を読む → "直球キーワード" と "周辺キーワード" の両方を出す。**
サービス名の直球ワード（例：ロゴ制作）だけに絞らない。ターゲットがその手前・周辺でやっている行動まで拾う（SIX/chics で実績のある勝ちパターン）。

|---|---|---|---|---|---|
| **SIX（chics）** | chics.top | ロゴ・VI 制作専門 | 独立/起業する人・リブランディング企業・法人設立 | ロゴ制作／VI／ブランドロゴ | 退職届の書き方・起業準備・創業補助金・法人設立の流れ・屋号の決め方・名刺 |

## 3. 役割分担（コスト最適の肝）

| 工程 | 担当 | 理由 |
|---|---|---|
| キーワード候補のアイデア出し | **クロコ（Claude）＝無料** | アイデアはClaudeで十分。ここに課金しない。 |
| リアルな検索実態（Googleサジェスト等）の発見 | **ラッコキーワードAPI**（少量） | 人が実際に打っている語を拾う。自分では思いつかない発見用。 |
| 検索ボリューム（本物の数字）の取得 | **ラッコキーワードAPI** | Claudeは推測しかできない。需要の裏取り＝ラッコの本命価値。 |

流れ：
```
① クロコが各サイトのターゲット行動導線からキーワード候補を出す（無料）
② ラッコAPIでサジェスト発見＋検索ボリューム取得（本物のデータ）
③ ボリュームのある「筋の良いもの」だけを各サイト 5〜8個に絞る
④ スプレッドシートに日付つきで追記
```

## 4. データソース：ラッコキーワード API

- プラン：スタンダード（月額 2,475円〜）。API はこのプラン以上で利用可。
- 月間 3,000 クレジット。API 経由は消費 1.5倍（＝実質 約2,000回分/月）。
- 入力方式：**シード（種）キーワード単位**。ドメイン登録ではない。→ サイトごとに「種キーワード」を定義して投げ分ける＝方向性の仕切りになる。将来サイト/他社が増えても種を足すだけで無制限に拡張可能。
- 取得できるもの：関連キーワード・サジェスト・月間検索ボリューム・CPC・競合性。
- APIキーは最大5個発行可。仕様書は JSON（Claudeが直接読んで実装できる）。

### 使用量の見積もり（実ペース基準）
- 実制作ペース：5サイト × 週2記事 ＝ 月40記事程度。
- 必要キーワード：選ぶ余地込みで月40〜100程度。
- → 月2,000枠に対し使用は数%。**クレジットは全く問題にならない。** スタンダードで十分。

## 5. 実行タイミング

- **週2回：月曜・木曜の早朝に自動実行**（クロコのスケジュール実行機能で無人起動）。
- **月曜＝定番（検索ボリューム大の王道）／木曜＝トレンド（最近伸びた旬）** で性格を分ける。

## 5-1. 抽出ルール（確定・2026-07-13）
- **1サイト 8個／回**（月・木それぞれ）。
- **検索ボリューム 100以上のみ採用**（50未満は捨てる。20等の低ボリュームは書く価値なし）。
- **重複除去**：書き込み前に既存キーワードを全読み込みし、既出（表記ゆれ・スペース違い含め正規化して一致）は除外。1回目と4回目がかぶらない。
- **区分**：定番（高ボリューム王道）／トレンド（firstSeenが新しい旬。ただしニッチ・低ボリュームになりがちで、100以上を満たすトレンドは毎回は出ない＝0の週もある）。
- **幅広くOK／誤解属性はNG**：シーン（ギフト・防災・内祝い・お取り寄せ等）は幅広く取る。ただし商品が持たない属性（例：A CURRYは無添加ではない→「無添加カレー」）や他社商品名は、検索者に誤解を与えるため除外。
- **種別末尾「C」＝クロコ発案**（クロコが切り口から独自に発案した語。ただし検索ボリューム100以上を満たすもののみ。空振りは載せない）。
- **井戸が枯れたら**：定番の高ボリューム語を取り尽くしたら、ロングテールに降りる／新しい切り口をクロコが発案／枯れてきたら報告（黙って重複を出さない）。

## 5-2. スプレッドシート列（確定）
No.（連番）／抽出日／キーワード／種別／区分（定番・トレンド）／検索ボリューム／SEO難易度（0〜100・低いほど易しい）／ステータス（手動）／ブログカテゴリ（手動）／校正チェック日（手動）／アップ日（手動）／記事URL（手動）／アクセス数（自動）

## 5-3. 各サイトの誤解NG・注意（確定）
- **毎回クロコが精査してから書き込む**：自動抽出はゴミ（無関係語・他人のIP・別ジャンル）を拾うため、書き込み前にクロコが候補をチェックし誤爆を弾く。NGリスト＋判断の二段構え。
- **A CURRY**：無添加ではない（コンセプト＝「あ！となる一皿／Say Ah!」味・ギフト訴求）。「無添加カレー」等は誤解を与えるため除外。ギフト・高級・おすすめ・防災・内祝い・お取り寄せは幅広くOK。他社商品名（葉山牛・無印・カルディ等）除外。
- **CHICS・YEARS（ロゴ系）**：**他社ロゴ画像が必要になる「ロゴ一覧・有名企業ロゴ・ロゴ事例」系は除外**（画像集め・権利処理が大変）。「◯◯な会社◯選」等のテキストで書ける記事はOK。他人のIP・別ジャンルの「記念」（有馬記念・ポケモン周年・Google創立◯周年等）も除外。
- **APOLLOS**：スマホ購入・EC等の「◯◯方法」ノイズ（pixel/iphone等）を除外。
- **BIRTH**：補助金の事後事務（状況報告・実績報告＝受給済み＝発注客でない）を除外。
- 選定基準：**ボリューム大 × SEO難易度低のバランス**（総合スコア）で上位を採用。切り口の幅はラウンドロビンで担保。

## 6. 出力：Google スプレッドシート

- スプレッドシートは1つ。中にサイトごとのタブ（シート）を分ける。
- タブ構成：`全体まとめ` ／ `APOLLOS` ／ `SIX` ／ `YEARS` ／ `A CURRY` ／ `BIRTH`
  - 各サイトのタブには、そのサイトのキーワードだけが貯まる（混ざらない）。
  - `全体まとめ` は全サイト横断で一覧するための集約タブ。
- 列（各タブ共通）：

| 列 | 入力 | 内容 |
|---|---|---|
| 抽出日 | 自動 | YYYY-MM-DD |
| キーワード | 自動 | 抽出した語 |
| 種別 | 自動 | 直球／周辺（導線） |
| 検索ボリューム | 自動 | 裏取りした実数字（アイデア候補は空欄可） |
| ステータス | 手動 | 生成済み → 校正中 → 校正OK → アップ済み（＝今誰のタスクか分かる縦ライン） |
| ブログカテゴリ | 手動 | 一旦空欄で用意（後で決める） |
| 校正チェック日 | 手動 | 校正した日 |
| アップ日 | 手動 | 記事を公開した日 |
| 記事URL | 手動 | 記事ができたら貼る（アクセス数取得のカギ） |
| アクセス数 | 自動 | 記事URLから定期取得（2〜3日に1回） |

- 「自動」＝クロコが記入。「手動」＝ケイスケさん側（生成／校正／アップ担当）が記入。役割の流れが横一列で追える。
- ステータスは生成→校正→アップで担当者が分かれる運用を想定した進行管理列。
- **上書きしない。** 抽出のたびに行を追記して蓄積する（キーワード資産を貯める）。
- 重複は追記時にクロコが除去（既存キーワードと突き合わせ）。
- 将来サイト/他社が増えたら **タブを1枚足すだけ**。

### 6-1. アクセス数の自動更新
- 記事URLがあれば、**GA4 または Google Search Console のAPI**から該当URLのアクセス数を定期取得して自動記入。
  - GA4＝ページ閲覧数（PV）／Search Console＝そのキーワードの検索クリック数・表示回数（SEO観点ではこちらが有益）。
- 頻度：2〜3日に1回、貼られているURLを巡回して更新。
- 条件：対象サイトが GA4／Search Console に接続されていること。A CURRY（Amazon商品）はブログURLの概念が異なるため対象外または別扱い。

### 6-2. 共有・連携（セキュリティ）
- スプシの共有設定は **「特定のユーザーのみ」（非公開）**。一般公開はしない。
- 追加メンバー：①ケイスケ本人 ②校正／アップ担当 ③自動化用のサービスアカウント（編集者）。
- 連携方法：
  - お試し段階（手動実行）＝ケイスケの既存Google連携でそのまま書き込み。サービスアカウント不要。
  - 自動化ON（月・木 無人実行）＝Google Cloud で無料発行するサービスアカウント（ロボット用の鍵。ログイン管理不要）をスプシに編集者招待し、非公開のまま無人書き込み。発行手順は実装フェーズでクロコが案内。

## 7. 段階的な立ち上げ（失敗しないため）

1. **A CURRY 1サイトだけ手動実行** → 出てくるキーワードの質をケイスケが確認。
2. 質OKなら **5サイトに拡大**。
3. 良ければ **月・木 早朝の自動実行をON**。

いきなり全サイト自動化しない。1サイトで質を確認してから広げる。
