# 音声タスク追加アプリ 設計書

作成日：2026-07-28
用途：ケイスケさん個人用。出先でブラウザを開いてすぐ録音し、話した内容をそのまま指定スプレッドシート（タスク管理表）の一番上に新規タスクとして追加する。音声メモアプリ（2026-07-17）の「開いて即録音」体験を踏襲しつつ、保存先をFirestoreではなくGoogleスプレッドシートに変える。

## 目的とゴール
- 開いた瞬間に録音を始められる（1タップ）。
- 話し終わったら**確認画面なしで即座に**指定スプレッドシートへ新規行として追加。
- 既存のタスク行は一切消さず、常に一番上（ヘッダー直下）に積み上げる。
- **自分専用**。売上等の機密情報も載っている表のため、他人がURLを知っても書き込めないようにする。

## 対象スプレッドシート
- URL: `https://docs.google.com/spreadsheets/d/1nZ5A991aTfNPNZdSDq2XWcUj55lMT7qhGkQCfD7P0s4/edit?gid=0#gid=0`
- 対象シート：`gid=0`（スプレッドシート内の最初のシート）
- 実際の行構成（CSVエクスポートで確認済み）：
  - 1行目：ヘッダー（B列`1st` / C列`2nd` / D列`状態` / F列`備考`。A・E列は無題）
  - 2行目以降：データ行（例：`,0,1,01_TODO,カレーショピファイ移行,,...`）

## 画面構成
1. **ホーム画面**：大きな「● 録音」ボタンのみ。中央寄せ、音声メモアプリと同じ見た目（URW DIN・赤い円ボタン）。
2. **録音中**：リアルタイムで文字起こし結果を画面に表示（確認用の可視化のみ、編集はしない）。
3. **録音停止と同時に**：認識済みテキストをGAS Web Appへ送信 → 成功したら「追加しました」の完了表示 → 数秒でホームに戻る。
4. **送信失敗時**：エラーメッセージを表示し、同じテキストで再送できるボタンを出す。

## 技術構成
- **文字起こし**：ブラウザ内蔵 Web Speech API（`ja-JP`・continuous・無料）。Chrome推奨（音声メモアプリと同様の割り切り）。
- **書き込み**：Google Apps Script（GAS）を対象スプレッドシートに紐付け、Web Appとして公開。
  - デプロイ設定：「実行ユーザー：自分」「アクセスできるユーザー：自分のみ」。
  - `doPost(e)`が受け取ったテキストを、`gid=0`のシートの2行目に`insertRowBefore(2)`で新規行を挿入。
  - 挿入する値：B列=`0`、C列=`0`、D列=`01_TODO`、E列=受け取ったテキスト、F列=空欄。
- **ホスティング**：GitHub Pages（`01_CRATER`リポジトリ内に新規フォルダ、`view.crater.co.jp/[フォルダ名]/`で公開）。Firebase等の追加インフラは不要。

## アクセス制御
- GAS Web Appを「アクセスできるユーザー：自分のみ」で公開し、Googleアカウントのログインセッションで認証する。
- **実装時の検証事項**：制限付きGAS Web Appに対してクロスオリジンの`fetch`でPOSTする構成は、認証の扱い上うまく通らないケースがある。動作確認して問題があれば、以下のフォールバックに切り替える：
  - フォールバック案：GAS側を「アクセスできるユーザー：全員」に緩め、リクエストボディに秘密のトークン文字列を含めてGAS側で一致確認する（一致しなければ書き込み拒否）。この場合の防御レベルは「URLとトークンの両方を知っている人だけが書き込める」＝音声メモアプリのURL非公開運用と同程度。

## エラー処理
- 音声認識結果が空文字のまま録音停止した場合は送信しない。
- GASへの送信が失敗（ネットワークエラー・権限エラー等）した場合はエラー表示し、再送ボタンを出す。二重送信を防ぐため送信中はボタンを無効化する。

## テスト方法
- 実際にブラウザで録音→文字起こし→送信を行い、対象スプレッドシートの2行目に正しい値（B=0, C=0, D=01_TODO, E=発話内容）で行が追加され、既存行が下にシフトすることを目視確認する。
- 他のGoogleアカウント（またはログアウト状態）からのアクセスで書き込みが拒否されることを確認する。

## スコープ外（YAGNI・今回はやらない）
- 送信前の確認・修正画面（「話し終わったら即送信」を採用したため）。
- カテゴリー自動判定・AIタグ付け（音声メモアプリのPhase 3構想とは別軸）。
- 複数シート・複数スプレッドシートへの出し分け。
- 音声ファイル自体の保存（テキストのみ）。

## リスク・留意
- Web Speech APIはChrome前提。Safari等では精度・安定性が落ちる。
- GAS Web Appの「自分のみアクセス」とクロスオリジンfetchの相性は実装時に検証が必要（上記フォールバックあり）。
- 文字起こし精度はそこそこ割り切り。誤認識のまま送信されるため、シート側で目視・手直しする運用とする。
