# ロゴ案件ウォッチ（設計）

## 目的
- 行政・団体の **ロゴ（周年ロゴが中心）** と **VI・ブランディング** の募集を毎日集め、HTMLの一覧に貯め、新着をLINEで知らせる
- 一番の狙いは100万円規模の **業務委託（入札・公募型プロポーザルなど）**。数が少ないので **公募・コンペ** も合わせて出す
- 2026-09-11 ケイスケさんの依頼で作成

## 動き
- GitHub Actions で毎日 **9:00 と 17:00（日本時間）** に自動で動く（`.github/workflows/ロゴ案件ウォッチ.yml`）
- 手で動かすとき：GitHub の Actions → 「ロゴ案件ウォッチ」→ Run workflow

## 集める先
| 集める先 | 何が取れるか | 方法 |
|---|---|---|
| 国の官公需情報ポータルサイト検索API（中小企業庁） | 入札・プロポーザル | 直近21日を言葉で検索（ロゴ・シンボルマーク・校章・ブランディング・VI・CI など） |
| 役所・団体サイトの新着RSS | 役所の公募・プロポーザル・デザイン募集 | `役所RSSさがし.py` が作った一覧（`data/役所RSS.json`）を全部見る。一覧は毎月1日の朝に作り直す |
| JDN「登竜門」 | デザイン公募・コンペ | RSS（ロゴ・マーク・キャラクター／グラフィック／ビジネス・アイデア） |
| 公募ナビ | デザイン公募・コンペ | RSS（ロゴ・シンボルマーク／全体）。記事ページは読みに行かず、RSSに載っている範囲だけ使う |

使わないもの：Koubo（RSSがなく、AIでの利用に条件あり）

## 絞り込み
1. タイトルの言葉で候補にする：ロゴ／シンボルマーク／記念マーク／校章／マーク募集・デザイン／ブランディング／ブランドデザイン・戦略・構築／VI／CI など
   - 国のAPIは案件名がPDFのファイル名になっていることがあるので、名前を戻したうえで本文の冒頭も見る
2. 除外する言葉：ベンチマーク／マークカード／マタニティマーク／プライバシーマーク／ロゴ掲出／使用承認／決定しました／結果発表 など
3. AI（Claude Sonnet。GitHub上ではサブスクの認証を使う）が本文を読んで、「新しくロゴ・VIを作る人の募集か」を判定し、項目を読み取る
   - 1回にAIで読むのは40件まで（使いすぎ防止。残りは次回）

## 読み取る項目
種類（業務委託／公募・コンペ）・分野（ロゴ／VI・ブランディング）・周年かどうか・案件名・主催・都道府県・金額（上限額・予定価格／賞金）・募集開始日・締切（一番近いものとその種類）・その他の締切・応募資格・**応募点数（1人何点まで）**・ひとこと

## 出し方
- 一覧：`output/ロゴ案件一覧.html`（view.crater.co.jp で公開・検索エンジンには載せない設定）
  - 業務委託を上に、金額を大きく表示。締切7日以内は赤。締切を過ぎたものはグレーで下に
  - 絞り込み：すべて／業務委託／公募・コンペ／周年／VI・ブランディング
- LINE：受付中の新着だけ、1回に最大8件＋一覧のURL。新着がなければ送らない
  - 初回だけ「はじめました」として受付中のまとめを送る

## 記録
- `data/案件.json`：判定したもの全部（対象・除外・重複・未判定）。一度判定したものは読み直さない
- 同じ募集がJDNと公募ナビなど複数に出ている場合は1件にまとめ、ほかの掲載先をリンクで添える

## 気をつけていること
- JDN・公募ナビの内容は、タイトル・締切・賞金・リンクなどの事実だけを載せ、記事本文は写さない
- 役所サイトには控えめに取りに行く（1日2回・同時24本まで・名乗り付き）

## ファイル
- `収集.py`：本体（集める→絞る→AI→貯める→一覧→LINE）
- `役所RSSさがし.py`：役所サイトの新着RSSを探して一覧にする
- `data/案件.json`・`data/役所RSS.json`
- `output/ロゴ案件一覧.html`
